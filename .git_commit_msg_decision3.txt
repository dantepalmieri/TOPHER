Replace fixed pipeline with a real, bounded multi-agent conversation

The 5-agent team no longer runs as a hardcoded Architect -> Research ->
Developer -> Testing -> Analytics relay. Each turn, the current
speaker sees the full transcript so far and ends its reply either with
an explicit @AgentName handoff to a specific teammate, or DONE once
the goal is satisfied. If neither, the orchestrator falls back to a
deterministic round-robin over the same canonical order the old
pipeline used, so the default trajectory still resembles the original
5-step shape - the real dynamism comes from agents choosing to jump
straight to a teammate (e.g. Testing kicking a fix back to Developer).

A hard MAXIMUM_CONVERSATION_TURNS cap (10) guarantees the loop always
terminates even if nobody says DONE; hitting it lands a new
RUN_STATUS_MAX_TURNS status, distinct from both a clean DONE finish
and a crash. New `messages` SQLite table (run_store.py) and TeamMessage
type persist the conversation; the dashboard now shows it live as a
message thread (MessageThread/MessageBubble) instead of a static
5-card status board, with each bubble showing who it addressed or that
it ended the run. solo_research runs are untouched - still a single
stage on the old PipelineStageResult/stages path.

Every agent's prompt gets the same shared handoff/DONE convention via
a new conversation_protocol.py, mirroring how identity.py already
avoids five hand-copies of shared wording.

Note on cost: each turn is a full Claude Code CLI subprocess call
against the user's Pro/Max subscription usage-limit window (see
decision 4), not metered per-token billing - this conversation model
can make up to double the calls per goal that the old fixed pipeline
did.
